# Field Test Facilitator Checklist

A short, printable/copyable checklist for running a real Applied AI
Discovery field test. See
[docs/real-applied-ai-field-test-guide.md](real-applied-ai-field-test-guide.md)
for the full process, disclosure language, and scoring rubric this
checklist is drawn from. **Remote call?** See
[docs/remote-conversation-capture-guide.md](remote-conversation-capture-guide.md)
for capture setup options (BlackHole, external mic fallback) and the
pre-call audio test below.

## Before the meeting

- [ ] Confirmed this meeting is an appropriate field test (permissioned,
      not overly confidential, not high-stakes legal/medical/financial).
- [ ] Created an Applied AI Discovery meeting with a real goal, current
      understanding, and a tentative build direction framed as a
      hypothesis.
- [ ] Generated the pre-meeting brief and skimmed "Patterns to validate."
- [ ] Decided on disclosure wording and how/when to say it.
- [ ] Decided on capture mode (live/manual/mixed) and prepared a manual-
      notes fallback.
- [ ] **Remote call only:** ran the pre-call audio test (start capture,
      play remote-style audio, speak one sentence, check whether the
      remote voice - not just your own - shows up usably) and recorded
      the planned setup in the Live page's Remote capture setup panel.

## Opening script

Say something close to this, in your own words:

> "I'm using a discovery assistant to help me track open questions and
> summarize the workflow today. It may capture transcript text or
> microphone audio depending on the setup. The outputs are working notes
> I'll review before sharing or acting on anything. Let me know if
> you'd rather I not record, and we'll go with manual notes instead."

## During the meeting

- [ ] Stakeholder relationship first - the tool supports you, it doesn't
      run the conversation.
- [ ] Use suggested directions in natural pauses, not mid-sentence.
- [ ] Don't read every suggestion aloud - pick what actually fits.
- [ ] One discovery thread at a time.
- [ ] Mark threads covered/deferred rather than forcing every topic in.
- [ ] Treat AI suggestions as prompts, never instructions.
- [ ] Mixed mode: let capture run in the background and use the Quick
      anchor note (Live page) for one-line critical claims only - not a
      parallel transcript.

## If DiscoveryOS gets distracting

- [ ] Pause capture.
- [ ] Switch to manual notes for a stretch, then resume later.
- [ ] Close the live HUD entirely if it's pulling your attention from the
      stakeholder - the meeting matters more than the tool.
- [ ] Note what was distracting for the debrief (section below) so it can
      actually get fixed.

## After the meeting

- [ ] Generated the post-meeting review.
- [ ] Generated the Applied AI opportunity assessment.
- [ ] Checked pattern fit - top fits, missing evidence, capped
      high-autonomy patterns.
- [ ] Spot-checked a couple of evidence quotes against the real
      transcript.
- [ ] Reviewed "still unclear" items and "possible mismatches."
- [ ] Decided what (if anything) to export/share.
- [ ] Logged pilot notes and/or tracked pilot issues if useful.

## Debrief scoring

On the meeting's Review page, under "Field test debrief," score 1-5:

- [ ] Helped ask better questions
- [ ] Reduced missed follow-ups
- [ ] Improved workflow understanding
- [ ] Stayed non-distracting
- [ ] Evidence felt trustworthy
- [ ] Applied AI judgment was useful
- [ ] Overall usefulness

1 = harmful/confusing · 2 = mostly not useful · 3 = mixed but promising ·
4 = useful with minor issues · 5 = clearly useful

Then record a success decision (strong signal / mixed signal / weak
signal / not enough data) and next-iteration notes.

**Remote call only:** also score "Capture quality (remote calls)" in the
same debrief section - remote audio clarity, user voice balance,
transcript usefulness (each 1-5), manual notes needed and HUD distraction
(low/medium/high), and which capture setup you used. See
[docs/remote-conversation-capture-guide.md](remote-conversation-capture-guide.md).
